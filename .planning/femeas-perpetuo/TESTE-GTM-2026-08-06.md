# Teste de GTM e conversão — 06/08/2026

**Resultado em uma frase: se a campanha subisse hoje, o Meta receberia apenas
`PageView` e otimizaria por tráfego, não por lead. A conversão de fêmeas não
dispara.**

Feito **sem credencial de GTM**, e por isso vale explicar como: o container
`GTM-K8RXFDDT` é servido publicamente em `googletagmanager.com/gtm.js?id=…`.
Baixá-lo e lê-lo mostra a configuração **publicada** — tags, condições e a
ligação entre elas. Não mostra o que está pendente dentro de um workspace.

## 1. O que está publicado no container

```
version: 9 · 5 tags · 19 macros · 6 condições
```

Idêntico à auditoria de 27/07 (`.planning/leilao-sao-geraldo/GTM.md`). **As
alterações do São Geraldo nunca foram publicadas** — o leilão rodou assim.

**As 6 condições publicadas:**

| # | Condição |
|---|---|
| 0 | evento == `gtm.init` |
| 1 | evento == `gtm.dom` |
| 2 | evento **contém** `gtm.` |
| 3 | evento **casa** `.+` (qualquer coisa) |
| 4 | **URL contém `/obrigado-jmp.html`** |
| 5 | evento == `gtm.js` |

**As regras (quem dispara com o quê):**

```
se evento == gtm.init                    → tag 0
se evento == gtm.dom                     → tags 1, 2, 3
se evento casa ".+" E NÃO contém "gtm."  → tags 2, 3      ← o acionador CATCH-ALL
se URL contém "/obrigado-jmp.html"       → tag 4
```

**As 5 tags:**

| # | O que é |
|---|---|
| 0, 1 | Google tag (GA4 `G-X00P526WF7`); a segunda com `send_page_view: false` e `transport_url` para um container server-side |
| 2 | Evento GA4 — **o nome do evento é o próprio evento do dataLayer** |
| 3 | Meta pixel `1539780341180483`, evento **variável** |
| 4 | Meta pixel `899641089812500`, evento fixo **PageView** |

> ⚠️ **A única condição por URL do container inteiro aponta para
> `/obrigado-jmp.html`** — a landing antiga do JMP. **Não existe nenhuma
> condição para `/obrigado-femeas-mql`, `/obrigado-femeas-lead`, nem para as
> páginas de obrigado de touros ou São Geraldo.**

## 2. A peça que decide tudo: a tabela de tradução

A tag 3 (Meta) e a tag 2 (GA4) tiram o nome do evento de uma **tabela de
consulta** sobre o evento do dataLayer, com **passagem direta como padrão**:

```
gtm.dom        → PageView
page_view      → PageView
generate_lead  → Lead            ← esta linha é a chave
sign_up        → CompleteRegistration
purchase       → Purchase
…
(qualquer outro) → o próprio nome, sem tradução
```

**Consequência:** o container **já sabe** transformar um `generate_lead` do
dataLayer em um evento `Lead` no Meta. Ninguém precisa criar tag nova para isso
— precisa apenas que alguém empurre o evento.

## 4. As duas saídas, e elas não são equivalentes

### (A) Criar o gatilho no GTM — precisa de acesso

Criar um acionador de Page View com `Page Path` contendo `/obrigado-femeas-` e
ligá-lo a uma tag do Meta com evento `Lead`, com valor diferente por variante.

- ✅ Não mexe em código.
- ❌ **Precisa de acesso ao GTM, que ninguém aqui tem.**
- ⚠️ **E publicar o container arrasta junto qualquer alteração pendente no
  workspace 10** — inclusive as 4 do São Geraldo, que nunca subiram. Conferir a
  aba "Alterações" **antes** de publicar não é zelo, é o que evita subir
  trabalho de terceiro sem querer.

### (B) Empurrar `generate_lead` no dataLayer da página de obrigado — só código

A tabela de tradução **já mapeia `generate_lead → Lead`**, e o acionador
catch-all já dispara as tags 2 e 3 para qualquer evento que não comece com
`gtm.`. Um único push na página de obrigado produziria, sem tocar no GTM:

- GA4: evento `generate_lead`
- Meta: evento **`Lead`**, com `value`/`currency` se forem enviados junto

⚠️ **Isto tensiona o INV-2**, que proíbe o `analytics.ts` de fêmeas de tocar o
`dataLayer`. Vale ler o invariante pelo motivo dele: ele existe porque o
acionador catch-all dispararia Meta/GA4 **a cada micro-evento do funil**
(`femeas_step_reached`, `femeas_validation_failed`…), inflando PageView. **Um
único push, só na página de obrigado, não é esse caso** — não duplica PageView
(que vem do `gtm.dom`) e é exatamente o desenho que a tabela de tradução
antecipa.

**Recomendação: (B), com o push restrito à página de obrigado**, e (A) depois,
quando houver acesso, para separar valor de MQL e não-MQL na própria tag.

⚠️ **Não implementei (B).** Mexe na medição, tensiona um invariante escrito, e
a decisão é do dono do projeto.

## 5. O que este teste NÃO cobriu

1. **O workspace do GTM.** Só a versão publicada é pública. Se houver alteração
   pendente, ela não aparece aqui.
2. **O container server-side** (`server-side-tagging-3hk3e67aaq-uc.a.run.app`).
   A tag 1 aponta para lá com `send_page_view: false`; o que acontece depois do
   `transport_url` não é observável do navegador.
3. **Produção.** Tudo foi medido em `localhost:3000`. As condições publicadas
   não checam host, então o comportamento deve ser o mesmo — mas "deve" não é
   "foi medido".
4. **A origem do `touros_mql`**, registrada acima como anomalia aberta.
